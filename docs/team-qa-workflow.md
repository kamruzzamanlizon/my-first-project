# Annotation Team QA Workflow

This is a scalable sample workflow informed by experience coordinating a 40-person annotation team. It is a framework, not a claim about a specific employer’s internal process.

## 1. Prepare
- Confirm task scope, class definitions, edge cases, output format, and deadline.
- Share the current guideline and approved examples.
- Identify questions that require lead/client clarification.

## 2. Align the team
- Explain task expectations before production begins.
- Use a small calibration exercise where appropriate.
- Discuss disagreements and document the agreed interpretation.
- Make sure updates reach all relevant annotators.

## 3. Production and review
- Track task assignment and completion.
- Review work against the same criteria.
- Record errors by category and severity.
- Return actionable feedback with examples.
- Escalate ambiguous cases instead of allowing inconsistent assumptions.

## 4. Monitor quality and delivery
Suggested tracking fields:

| Metric | Why track it |
|---|---|
| Assigned items | Work allocation |
| Completed items | Progress |
| Reviewed items | QA coverage |
| Issues by category | Error pattern visibility |
| Rework status | Correction tracking |
| Pending questions | Blockers and ambiguity |
| Delivery status | Deadline management |

Do not report a quality score unless the sampling method, denominator, and scoring rules are defined.

## 5. Improve
- Identify recurring error patterns.
- Update examples or guidance when clarification is approved.
- Provide targeted coaching.
- Recheck a later sample to evaluate whether the issue has reduced.
- Keep a record of decisions and guideline versions.

## Escalation path

1. Annotator identifies an unclear case.
2. Reviewer checks the written guideline and available examples.
3. Team lead reviews unresolved ambiguity.
4. Client/project owner confirms the rule when necessary.
5. Approved clarification is shared with the team.

## Team lead responsibilities

- Maintain consistent review standards.
- Communicate priorities and blockers.
- Give respectful, evidence-based feedback.
- Coordinate workload and follow-up.
- Protect project confidentiality.
- Report progress and risks accurately.
